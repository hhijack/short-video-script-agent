# 01-requirements.md — 用户、目标、范围和成功标准

> 本文档定义项目的用户、目标、范围与成功标准。

## 用户与目标

- **用户**：短视频创作者（尤其新手），需要快速产出「有事实依据、满足时长限制、可直接编辑」的口播脚本。
- **目标**：给定主题、受众、平台、目标时长与风格，Agent 产出结构化脚本（标题、分镜、旁白、字幕、预计总时长、素材来源 ID、风险与任务状态），且脚本中每个产品事实都能追溯到素材库原文。

## 输入与材料

| 输入 | 说明 | 缺失时的行为 |
| --- | --- | --- |
| topic | 脚本主题，同时是素材检索关键词 | **关键信息**，缺失即请求补充（case2） |
| target_duration_sec | 目标时长（秒） | **关键信息**，缺失即请求补充（case2） |
| audience / platform / style | 受众 / 平台 / 风格 | 有默认值（泛短视频用户 / 抖音 / 轻松口播），不阻塞 |

- **材料**：`data/materials.json` 合成素材库（P01–P05，虚构产品「映记」）。每条素材只含 `facts`（产品事实）与 `effect_data`（带数据的效果结论）；P01 严格保持参考样例口径——仅包含「支持字幕」这一条产品事实，无任何效果数据。
- **规则**：`data/brand_rules.json` 品牌规则（时长区间、绝对化用语、事实可追溯等 6 条）。

## 工具（全部本地 Mock，`src/tools.py`）

1. `search_materials` 素材检索：关键词打分，可复现；
2. `read_material` 素材读取：按 ID 返回素材全文（事实/效果数据原文）；
3. `estimate_duration` 时长估算：确定性口径（4 字/秒、单分镜下限 1.5s）；
4. `check_rules` 规则检查：R1 时长区间、R2 绝对化用语、**R3 事实可追溯（反幻觉）**、R4 品牌名分镜须引用素材、R5 素材 ID 存在、R6 旁白语速。

## 范围

- **做**：CLI 运行、ReAct 决策循环、步数上限、4 个 Mock 工具、离线 Mock 模型入口、真实模型接入实现（OpenAI 兼容，走环境变量）、pytest 测试、examples 运行产物。
- **不做**（明确非必需）：Web 界面、线上部署、多 Agent、生产级 Runtime、真实素材库/发布通道。

## 成功标准

1. 5 个必须场景全部有真实运行证据（见 docs/03-evaluation.md）：
   ① 正常生成；② 缺关键信息；③ 无素材；④ 工具失败；⑤ 超时长后的修正或明确失败。
2. 脚本中每个产品事实/数字表述可追溯到素材 ID；素材中没有的效果数据（如「效率提升 80%」）被规则检查拦截（tests/test_tools.py::test_check_rules_r3_unsupported_effect_claim_is_violation）。
3. 至少两条执行路径的运行记录，体现模型因工具结果不同而做出不同动作（examples/*/trace.json）。
4. 达到工具调用上限时返回明确的未完成状态（case5），不静默截断。
5. `python3 -m pytest tests/ -q` 全部通过；`python3 -m src.cli run-all --out examples` 可复现全部产物。
